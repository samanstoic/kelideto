# ارزیابی امنیت و حریم خصوصی ـ فاز شانزده

**تاریخ ارزیابی:** ۱۹ اکتبر ۲۰۲۶  
**محدوده:** کد و فایل‌های قفل وابستگی همین مخزن؛ بازبینی دستی مسیرهای حساس و اجرای آزمون‌های محلی  
**وضعیت:** اصلاحات فنی گزارش‌شده در ادامه آزموده شدند؛ آسیب‌پذیری بحرانی شناخته‌شده‌ای در محدودهٔ مرورشده باز نماند. بازبینی مجدد یک نقص دسترسی متوسط در تیکت‌های پشتیبانی یافت و آن نیز اصلاح شد. MFA مدیر اکنون با Passkey اجباری شده است؛ بازیابی خودکار Passkey و دوره‌های نگهداری/رضایت و الزامات حقوقی هنوز باز هستند.

این ارزیابی گواهی امنیت، انطباق قانونی یا مجوز فعالیت نیست. نتیجهٔ ابزارهای خودکار فقط وضعیت نسخه‌ها و پایگاه‌های advisory در زمان اجرا را منعکس می‌کند. الزامات بازار هدف، مجوزهای صنفی، مبانی قانونی پردازش، نگهداری و حذف داده باید جداگانه و توسط متخصصان مربوط تأیید شوند.

## روش و محدودهٔ بازبینی

- مرور STRIDE و کنترل دسترسی/RBAC در ورود، پنل مدیر، سفارش‌ها، اعزام و موقعیت مشتری.
- مرور ریسک‌های OWASP مرتبط: احراز هویت و مجوز، IDOR، SSRF، XSS، CSRF، SQL injection، mass assignment، آپلود، سوءاستفاده از API و مدیریت اسرار.
- مرور مسیرهای دادهٔ شخصی/مکانی، لاگ‌های دسترسی، زمان نگهداری، رضایت، حذف و ناشناس‌سازی.
- بازبینی خروجی Composer/npm lock و advisory audit؛ ثبت محدودیت‌های ممیزی مجوزها در اقدامات باقی‌مانده.
- اجرای آزمون‌های Feature، آزمون‌های فرانت‌اند، lint، build و health check محلی.

## بازبینی دستی کنترل‌های حساس

- **مجوز و IDOR:** مسیرهای مرورشده از نقش/مجوز و مالکیت سفارش استفاده می‌کنند؛ آزمون مالکیت سفارش و کنترل نقش موجود موفق است. در مسیر نقشه، مأموریت فعال و بازهٔ زمانی محدود می‌شود و دسترسی عملیاتی ثبت می‌شود.
- **تیکت خصوصی:** فقط ثبت‌کنندهٔ تیکت و پشتیبانی فعال مجاز به دیدن پیام/پیوست هستند؛ طرف دیگر همان سفارش دسترسی ندارد.
- **SQL injection و mass assignment:** در مسیرهای مرورشده query builder/Eloquent و داده‌های اعتبارسنجی‌شده استفاده می‌شود؛ مورد قابل‌بهره‌برداری مشخص نشد.
- **XSS:** متن محتوای عمومی با escaping Blade نمایش داده می‌شود؛ preview فقط برای مدیر مجاز است. در مسیرهای بررسی‌شده مورد قابل‌بهره‌برداری مشخص نشد.
- **SSRF:** endpoint مسیریابی از تنظیم سرور استفاده می‌کند و مقصدهای بررسی‌شده تحت کنترل درخواست‌کننده نیستند؛ مورد SSRF قابل‌بهره‌برداری مشخص نشد.
- **CSRF و نشست:** APIهای مرورشده با bearer token احراز می‌شوند؛ تنظیم Sanctum برای دامنه‌های stateful و middleware CSRF حفظ شده است. بازبینی حاضر جایگزین آزمون نفوذ مستقل مرورگر/پروکسی نیست.
- **آپلود:** مسیرهای مرورشده برای فایل‌های حساس از فضای خصوصی و دسترسی کنترل‌شده استفاده می‌کنند و محدودیت نوع/اندازه دارند؛ داده‌های پیوست و مدارک همچنان به سیاست نگهداری و حذف نیاز دارند.
- **Brute force/API abuse:** OTP و ورود مدیر throttle دارند؛ کد OTP زمان انقضا و سقف تلاش دارد. نرخ‌محدودسازی وابسته به cache پایدار و تنظیم درست IP proxy در محیط عملیاتی است.
- **MFA/WebAuthn:** سرور با `laravel/passkeys` و `web-auth/webauthn-lib` challenge/attestation/assertion را اعتبارسنجی می‌کند؛ RP ID و originهای مجاز باید در تولید صریح و HTTPS باشند. challenge به نشست و حساب pending متصل، پنج دقیقه‌ای و تک‌مصرف است؛ user verification اجباری و توکن قبل از موفقیت صادر نمی‌شود. آزمون سخت‌افزار/مرورگر واقعی و بازیابی خودکار credential ازدست‌رفته در این اجرا انجام/پیاده نشده است.
- **اسرار:** `.env` محلی بررسی یا در این سند بازنشر نشده است. نمونهٔ Compose دیگر کلید ثابت ندارد. چرخهٔ عملیاتی چرخش اسرار تولیدی هنوز باید تعریف شود.
- **کتابخانه‌ها:** Composer و npm inventory از lockfileها استخراج شد. چند وابستگی PHP، از جمله `nette/schema` و `nette/utils`، مجوز دوگانهٔ BSD/GPL اعلام می‌کنند؛ این گزارش تفسیر حقوقی مجوز نیست.

## آزمون‌ها و بررسی‌های اجراشده

- `artisan test`: آخرین اجرای کامل ۹۹ موفق، ۱ skipped و ۷۸۷ assertion بود. پس از اصلاحات جدید، مجموعهٔ متمرکز پشتیبانی/موقعیت/اعزام/مدیر/تکنسین/امنیت: ۳۷ موفق، ۱ skipped و ۳۱۷ assertion.
- `npm test`: ۹۵ تست موفق در ۱۸ فایل.
- `npm run lint` و `npm run build`: موفق.
- `composer audit --locked`: بدون advisory پس از ارتقای Laravel.
- `npm audit` با registry HTTPS: صفر آسیب‌پذیری پس از ارتقای Vitest.
- در این بازبینی، `npm audit --audit-level=low`: صفر آسیب‌پذیری.
- `GET http://127.0.0.1:8001/api/health`: پاسخ ۲۰۰ و وضعیت healthy.

نتایج آزمون‌های بالا از اجرای قبلی ثبت شده‌اند. در بازبینی حاضر، PHP و Composer در PATH نبودند و Docker daemon نیز اجرا نمی‌شد؛ ابزار تست PHP صفر تست اجرا کرد. بنابراین آزمون‌های PHP و `composer audit --locked` برای اصلاحات تازه دوباره اجرا/تأیید نشدند؛ تحلیلگر PHP برای فایل‌های تغییرکرده خطای syntax گزارش نکرد.

این آزمون‌ها آزمون نفوذ بیرونی، fuzzing جامع یا تضمین نبود نقص ناشناخته نیستند.

## اقدامات باقی‌مانده

1. **حریم خصوصی و نگهداری:** مختصات مأموریت، telemetry، KYC، مدارک احراز اختیار، پیوست پشتیبانی، audit، مالی و نسخه‌های پشتیبان دوره‌های متفاوت می‌خواهند. مختصات متخصص هنگام آفلاین/تعلیق/پایان کار و telemetry بیش از ۱۵ دقیقه بی‌تازگی پاک می‌شود؛ این policy حذف سایر داده‌ها نیست. مدت‌های مجاز، مبنای پردازش، حذف/ناشناس‌سازی و اثر restore از backup باید از مالک کسب‌وکار/مشاور حقوقی دریافت شود؛ سپس jobهای حذف فایل و رکورد هماهنگ افزوده شوند.
2. **رضایت و شرایط:** وجود پذیرش نسخه‌دار و قابل‌ممیزی شرایط استفاده/حریم خصوصی در مسیرهای بررسی‌شده احراز نشد. پس از تصمیم حقوقی، نسخه، زمان، موضوع رضایت و لغو رضایت ثبت و آزمون شود.
3. **حقوق، مجوز و بازار هدف:** حوزه‌های فعالیت، مجوزهای کسب‌وکار، مدارک مجاز احراز مالکیت/صلاحیت، حقوق مصرف‌کننده، مالیات، پرداخت، انتقال داده و تعهدات اعلان رخداد با مشاور واجد صلاحیت تعیین شوند. این گزارش هیچ‌یک را تأیید نمی‌کند.
4. **رخداد امنیتی:** مراحل فنی triage/مهار/حفظ شواهد/بازیابی و postmortem در [incident-response.md](./incident-response.md) آمده است؛ مالک‌ها، مخاطبان اضطراری، زمان پاسخ و تعهد اعلان باید با واقعیت سازمان و نظر حقوقی تکمیل و تمرین شود.
5. **چرخش اعتبارنامه و MFA:** رویهٔ فنی در [secret-rotation.md](./secret-rotation.md) آمده است. secret manager و مالک credentialهای واقعی محیط تولید باید تعیین شوند. نگهداری/تجديد و بازیابی Passkey مدیر نیازمند runbook سازمانی با کنترل هویت و ثبت audit است؛ روش اضطراری خاموش‌کردن MFA طراحی نشده است.
6. **مجوز وابستگی‌ها:** تفسیر مجوزهای دوگانه و تعهدات توزیع همهٔ وابستگی‌های مستقیم/غیرمستقیم توسط مشاور حقوقی تکمیل شود؛ inventory استخراج‌شده به‌تنهایی تأیید مجوز محسوب نمی‌شود.
7. **پیکربندی تولید:** TLS، `APP_DEBUG=false`، دامنه‌های stateful/CORS، IPهای trusted proxy، cache/limiter پایدار، backup رمزگذاری‌شده و پایش audit در محیط نهایی بررسی و با تنظیمات واقعی آزموده شوند.
8. **اعتبارسنجی WebAuthn عملیاتی:** پیش از انتشار، دامنه و origin HTTPS واقعی، ثبت/ورود در مرورگرهای هدف، قطع/بازیابی session و فرایند بازیابی credential را در staging آزموده و runbook مالک‌دار ثبت کنید.
